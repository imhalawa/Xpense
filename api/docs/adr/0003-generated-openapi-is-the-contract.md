# The generated OpenAPI document is the contract

`docs/api/v1.0/v1.0.yaml` and the four files under `docs/api/v1.0/schemas/` are deleted. The
document generated by `AddSwaggerGen` and served at `/swagger/v1/swagger.json`
(`Program.cs:67-70`) is the API description, and `docs/contract/api-v1-contract-design.md`
keeps the design rationale that generated output cannot express.

## Why

Three descriptions of this API existed, and only one was accurate. The generated one is
accurate by construction, because it is built from the endpoints themselves. The hand-written
one had drifted so far that it described the API from before the v1 contract reset, and it was
not merely stale — it was invalid:

- `schemas/accounts/account.json` and `invalid-account.json` describe `topic` and `brief`,
  leftover template properties with nothing to do with accounts
- `schemas/transactions/transaction.json` and `invalid-transaction.json` are **empty files**,
  so the `$ref`s at `v1.0.yaml:53` and `:60` resolve to nothing
- `v1.0.yaml:260` — `GET /transactions` is documented as returning
  `#/components/schemas/Accounts`
- `v1.0.yaml:230` — the path key is `/transactions?search={search}&...`; a query string is not
  valid in an OpenAPI path
- `v1.0.yaml:262-271` — paging via `X-Page-Number` and `X-Total-Pages` headers, while the
  contract doc and `TransactionPageResponse` use a body envelope
- `v1.0.yaml:293` — `POST /transactions` returns `204`, while the contract doc specifies
  `201 Created` with a `Location` header
- only Accounts and Transactions appear at all; categories, tags, merchants, transfers and
  analytics are missing
- `servers` advertises `https://www.xpense.io/api`, which does not exist

The metadata disagreed too: `IoC.cs:70-79` says title "Xpense" and contact
`halawa.dev/about`; `v1.0.yaml:3-9` says "Xpense.API" and `www.halawa.dev`. The generated
document wins, and its metadata is corrected to match the contract doc.

## Considered options

**Fix it by hand and keep it.** Would give a contract independent of the implementation, which
is genuinely valuable once external clients exist. Rejected because it means writing four
schemas from scratch, repairing five separate defects, adding four missing resources, and then
keeping all of it in sync by hand forever — having just demonstrated that this does not happen.

**Delete it and commit a generated snapshot in CI.** A committed, generated document makes
contract changes visible in review, which is worth having once clients exist. Rejected for now
only as extra machinery ahead of the need; it is the natural next step, not a different
direction.

## Consequences

Contract changes are no longer visible as a diff in review — they show up only as code
changes. Revisit by adding the generated-snapshot step once there is a client that can be
broken.
