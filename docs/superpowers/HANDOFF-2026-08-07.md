## Deviations from the plan, and why

- **Vitest 4, not 3.** Vitest 3 requires Vite ≤7; this project runs Vite 8, so v3 would have pulled a
  duplicate Vite into `node_modules`.
- **`CssThemeVariables` augmentation in `theme.ts`.** Without it MUI 9 does not type `colorSchemes`,
  and the plan's own test failed to typecheck.
- **`import type React` in `typography.d.ts`.** The augmentation references `React.CSSProperties`
  inside a module.
- **`App.css` rewritten**, which the plan did not anticipate. It hardcoded a Lato font stack that
  fought the new theme, carried three comments against the project rule, hardcoded `#3163be` (a blue
  absent from the palette), and referenced `--scrollbarBG` and `--thumbBG` which **are defined
  nowhere in the project** — that scrollbar styling has been silently broken.

## Things found along the way that are not yet fixed

- **`vitest.config.ts` is not typechecked** — no tsconfig includes it.
- **`DeltaChip`'s dark colours ride on `colorSchemeSelector: "data-theme"`.** Its tests assert token
  contrast, not computed styles, so changing that selector would break the chip silently. Assert
  computed styles if this proves fragile.

## What was deliberately NOT done

**`/playbook` was not used.** It is incompatible with an unattended run, on four counts read from the
skill itself: it requires a Jira story key and Xpense has no Jira; it has three mandatory human gates
plus a per-subtask validation gate, and states "you are not the quality gate — the user is"; its
guardrail hooks hard-block commits past an unpassed gate and it forbids editing state to satisfy a
hook; and it stops after one subtask per session by design. Running it would have meant stalling or
falsifying a state file. The `tdd` loop plus subagents was used instead.

**The auth migration was not authored yet, and must not be auto-applied when it is.** Spec #4 sets out
a three-step expand/contract: add `Users` and a nullable `UserId` everywhere, backfill to the first
owner, then make it non-nullable. Step 2 rewrites the ownership of every row in a financial database
and is the only irreversible action in this backlog.
